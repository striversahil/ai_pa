Founder OS: WhatsApp + Zoho Estimates + telecalling CRM behind a Next.js dashboard.
**Live system is Cloudflare Worker (D1) + GitHub Actions runners.** Express/PostgreSQL shares modules but is NOT production.

## Runtime model
- `founder-os_backend/src/modules/*` + `src/automations/*` are dual-runtime (Worker + Express). No Node-only deps in shared modules — Worker build (`scripts/build-worker.mjs`) redirects via `REDIRECTS` to `*-worker.ts` twins.
- **Worker** = thin JSON API over D1. `src/worker.ts` (~40 lines) registers `src/worker/routes/*.ts` (~40 modules; that list is the inventory). Shared helpers: `context.ts` (`Bindings`, `bootstrapEnv`, `deps()`, `adminGuard`, `broadcastLive`, `createApp()`), `http.ts` (`readBody`, `writeError`), `viewer.ts` (`getViewer`/`getViewerMe`/`requireViewer`), `workspace-data.ts`. Never re-inline these.
- **Express `src/routes/` is FROZEN (founder decision): Worker-only for new endpoints.** Shared cores (`src/shared/*`, `src/modules/*`) stay dual-runtime. Don't add Express mirrors; existing ones maintained until removal.
- Cron router: `src/worker/cron.ts` (see below). Architecture truth: `architecture.md` (§5 cron, §9 deploy, §10 extension) — may lag code; verify against config/scripts.

## Cron (Cloudflare-only dispatch)
- ONE trigger `* * * * *`. `cron.ts` dispatches `workflow_dispatch` by **UTC minute alignment** (`min%5/10/15/30==0`, daily 02:30/13:30/19:30/21:30 UTC; 15:30 retired 2026-10-22; `inputs.slot` gates, `all`=manual). neodove-refresh runs natively every 5 min.
- **Gate on `event.scheduledTime`, never `new Date()`** (delivery lags 1–2 min). `cron-*.yml` have NO `schedule:` — don't re-add.
- Runners `scripts/*-runner.js` call `/api/runner/*` (Bearer `SHARED_SECRET`) and get AI **only** via `POST /api/ai/complete` on the Worker — `scripts/ai-gateway.js` is helper/KeyPool code, no local HTTP gateway and no env-key loader. Key pool: Setting `ai:providers` BYOK JSON ONLY (root-only UI, never echoed); env `AI_KEYS`/`OPENROUTER_*`/`REQUESTLY_*`/etc. are IGNORED (founder decision 2026-11-27); an empty Setting = an empty pool. Global `ai:strategy` = `least-used-first`|`round-robin`; groq keys NEVER loaded (founder decision 2026-09-21); sticky `sessionKey` pin; plain-429→cool+rotate immediately (no backoff sleep) / 1015→cool+rotate / 401→disabled / 404→whole provider quarantined 5 min / hang→first-byte (30 s) or first-token (20 s) deadline then rotate. 3 tries per provider leg, 6 pool-wide, a pinned key exactly once; total budget 120 s per leg. No lanes, no relay, no per-task providers.
- GH secrets: `WORKER_URL`, `SHARED_SECRET`, `NEODOVE_USER_IDS`. AI keys are NOT runner secrets — the Worker's Settings pool owns them. Dispatch secret: `GITHUB_ACCESS_TOKEN` via `printf | wrangler secret put` (no `echo`); `User-Agent` header required (handled).
- **Telecalling is deterministic (no LLM)**: `runLeadConversion()`; daily `POST /api/trigger/telecalling` 08:00 IST. EOD deduction / effort-sync / snatch-cover-bulk RETIRED (2026-10-22) → `{retired:true}` stubs.
- **Quiet hours 21:00–09:00 IST** (`isOpsWindow()`): 10/15-min dispatches skipped, 5-min fires (no Zoho pings), daily fires `run_neodove=false`, native refresh skipped.
