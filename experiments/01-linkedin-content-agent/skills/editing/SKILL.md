# Editing Skill — BUI

## Purpose
Refine a BUI draft in `content/drafts/` so it passes the **Section 12 quality checklist** before delivery. Refine, don't rewrite; if restructuring is needed, send back to writing with feedback.

## Input
- Topic file with `ready_for_edit: true` + `post_draft` (Hook A / Hook B / post / visual / hashtags / data-needed)

## Process
1. **Run the Section 12 checklist** (all must pass):
   - [ ] First line specific, creates curiosity (no "excited to announce")
   - [ ] At least one concrete number, example, or detail (or `[NEED DATA]`)
   - [ ] All numbers founder-provided or marked `[NEED DATA]`
   - [ ] No avoid-list buzzwords
   - [ ] Short paragraphs (max 2-3 lines)
   - [ ] Sounds like a practical founder, not a brochure
   - [ ] One clear takeaway; one soft CTA (question or offer), not pushy
   - [ ] 3-5 relevant hashtags; max 2-3 emojis
   - [ ] No customer named without permission; no unprovable claims
   - [ ] Policy/scheme details flagged `[verify before posting]`
   - [ ] 2 hook options present
   - [ ] Visual suggestion included (real photo/video idea per Section 10)
2. **Voice checks:** first-person founder; Indian units (Rs., tonnes, HP, kW, quintal, mandi); guarantees reworded ("in one case / in our experience / depending on conditions"); no competitor naming.
3. **Fact discipline:** any invented-looking number → replace with `[NEED DATA: ...]` or flag `[VERIFY]`; never silently weaken real data.
4. **Update file:** replace `post_draft` with refined version; set `edited_at`, `ready_for_image: true` (real-visual brief) or `ready_for_review: true`; keep `editor_notes` for flags.
